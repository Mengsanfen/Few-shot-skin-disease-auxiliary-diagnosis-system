# 第 1 章 作品概述

## 1.1 作品背景

随着“健康中国 2030”“互联网+医疗健康”以及人工智能赋能基层医疗等政策持续推进，医疗服务体系正在从经验驱动、单点诊疗向数据驱动、智能协同和全流程管理转型。皮肤疾病具有高发、易复发、表现形式复杂、图像特征差异明显但部分疾病高度相似等特点，患者常常依赖线下门诊完成初筛、复诊和健康管理。对于基层医疗机构、校医院、企业健康管理部门以及互联网医疗平台而言，如何在有限医生资源下快速完成皮肤问题初步分诊、影像辅助识别、知识库检索、风险提示和健康指导，已经成为智慧医疗落地中的典型需求。

现有多数医疗 AI 系统存在三个明显断点：第一，图像识别、问诊对话和知识检索彼此割裂，用户需要在多个工具之间反复切换，难以形成连续的诊疗辅助流程；第二，系统只给出孤立结果，缺乏证据链、知识图谱和参考依据，难以满足医疗场景对可信、可追溯、可解释的要求；第三，模型部署和业务系统集成门槛较高，难以在 GPU、CPU、内网、教学演示和企业私有化部署等不同环境之间灵活迁移。

DermoAI 针对上述痛点，构建了一套面向企业级使用场景的皮肤医学智能诊断与健康管理平台。系统以 Django 为 Web 应用底座，融合大语言模型、RAG 检索增强生成、医学知识库、知识图谱、SFEPT 小样本皮肤影像分类、YOLO 目标检测、Landing AI 开放词表检测、ECharts 数据可视化和多源 API 服务，形成“问诊输入—知识检索—证据增强—图像分析—大模型解读—数据看板—健康管理”的一体化闭环。

## 1.2 作品定位

DermoAI 不定位为替代医生的自动诊断工具，而定位为“企业级皮肤医学智能辅助平台”。其核心价值在于将皮肤医学问诊、影像辅助分析、知识库管理、健康内容服务和运营级数据监测整合到统一工作台，为医疗机构、健康管理企业、学校医务室、科研教学团队和互联网医疗产品提供可扩展、可解释、可部署的智能化基础设施。

系统面向三类典型用户：

- 患者或普通用户：通过自然语言描述症状、上传皮肤图像、获取初步风险提示、就医建议和健康管理建议。
- 医生或健康管理人员：查看问诊上下文、RAG 证据、知识图谱关系、图像分类结果和辅助分析报告，提高分诊和沟通效率。
- 平台运营与管理人员：通过可视化大屏观察问诊量、症状分布、知识库规模、RAG 命中情况和高风险待复核记录，支撑运营决策。

## 1.4 技术路线

系统技术路线可概括为“一体化 Web 工程底座 + 多模型智能服务编排 + 医学知识增强 + 轻量图谱解释 + 可视化运营反馈”。

1. 前端交互层采用 Django Template、HTML、CSS、JavaScript 与 ECharts 构建，统一为企业级医疗工作台视觉语言，覆盖首页、问诊、图像诊断、知识中枢、健康内容和数据大屏。
2. 后端服务层采用 Django 5.1，负责路由分发、会话管理、文件上传、模型调用、API 集成、知识库管理和权限扩展。
3. 智能问诊层采用 LangChain 组织 Prompt、LLM 调用、RAG 上下文拼装和流式输出，支持 DeepSeek 或兼容 OpenAI 协议的大模型服务。
4. 知识增强层通过结构化医学知识表、上传文档表和知识切片表构建检索索引，并将疾病、症状、检查、建议映射成轻量知识图谱。
5. 图像智能层使用 PyTorch 加载 SFEPT 皮肤疾病小样本分类模型，通过 Swin Transformer 提取特征，通过原型网络完成类别判别，并进一步结合大模型生成可读诊断建议。
6. 检测服务层同时支持本地 YOLO 检测和 Landing AI 开放词表目标检测，形成可迁移、可拓展的医学视觉能力接口。
7. 数据可视化层汇聚问诊会话、消息记录、知识库条目、风险关键词和趋势窗口，输出面向运营和管理者的数据看板。
8. 部署层通过环境变量统一管理数据库、API Key、模型路径、CPU/CUDA 推理设备和半精度开关，提升不同机器环境下的可部署性。

## 1.5 作品价值

DermoAI 的核心价值不在于单一模型的堆叠，而在于将医学 AI 的多个关键能力组合成稳定的产品化闭环。系统既能提供面向用户的皮肤问题咨询入口，也能提供面向医生和运营人员的证据化工作台；既能支持本地模型推理，也能对接云端大模型和外部检测服务；既能服务教学比赛演示，也具备向企业健康管理、互联网医疗平台、基层医疗辅助系统扩展的工程基础。

与传统单一问答系统相比，DermoAI 具备以下优势：

- 多模态闭环：文本问诊、图像分类、目标检测、知识检索和数据可视化在同一平台联动。
- 证据可追溯：每次问诊可返回 RAG 参考依据和知识图谱路径，降低大模型幻觉风险。
- 模型可迁移：推理设备支持 CPU/CUDA 配置切换，模型路径通过环境变量配置，便于跨环境部署。
- 数据可沉淀：问诊会话、消息记录、知识条目和文档切片都进入数据库，形成持续优化的数据资产。
- 产品级体验：页面不再停留在实验 Demo，而采用企业级工作台的信息架构与视觉表达。

# 第 2 章 问题分析

## 2.1 问题来源

皮肤疾病具有患病群体广、表现类型多、复发周期长、初筛需求高等特点。常见皮肤问题如湿疹、痤疮、银屑病、白癜风、色素痣变化、皮炎和真菌感染等，既可能是轻微生活方式问题，也可能隐藏较高风险。普通用户往往难以准确描述症状、判断严重程度和选择就医时机；基层医疗或企业健康管理场景也缺乏足够皮肤专科医生完成大规模初筛。

另一方面，移动互联网使患者更愿意通过线上方式进行初步咨询和图像上传，但传统线上咨询平台主要依赖人工回复，效率有限；部分 AI 问答产品虽然能生成语言建议，却缺少医学知识来源、图像分析能力和持续会话管理。对于皮肤医学场景而言，单纯文本问答无法充分利用图像信息，单纯图像模型又无法理解患者主诉、持续时间、诱因、既往史等上下文信息。

因此，面向皮肤医学场景，需要构建一套能够整合“文本、图像、知识、图谱、数据运营”的智能平台，实现从初步咨询到辅助识别、从知识增强到可视化管理的闭环。

## 2.2 现有解决方案

### 2.2.1 智能问诊大模型技术

近年来，大语言模型在医疗问答、病历摘要、诊前引导和健康科普中展现出较强的语言理解能力。基于 ChatGPT、DeepSeek、通义千问、讯飞星火等模型构建的医疗问诊系统，可以通过自然语言完成症状追问、风险提醒和健康建议生成。结合 LangChain、Prompt Engineering 和流式输出技术，系统可进一步提升交互体验。

但大模型直接用于医疗场景仍存在明显不足。首先，大模型可能出现医学事实错误或生成过度自信的建议；其次，通用模型对本地知识库、企业标准流程和专科知识的掌握有限；再次，大模型回答缺乏引用来源，医生和用户难以追溯依据。因此，医疗问诊系统必须引入 RAG、知识库、规则约束和风险提示机制，使生成内容“有依据、有边界、可复核”。

### 2.2.2 医学影像分类技术

医学图像分类是人工智能辅助诊断的重要方向。传统 CNN、ResNet、EfficientNet、Vision Transformer、Swin Transformer 等模型已经广泛用于皮肤镜、病理切片、X 光、CT、MRI 等图像识别任务。对于皮肤疾病识别，模型需要在有限样本下区分高度相似的皮损形态，同时处理拍摄光照、角度、清晰度和背景干扰。

现有图像分类方案普遍面临数据标注成本高、类别长尾分布明显、模型跨数据集泛化不足、解释性不够等问题。尤其在真实业务场景中，系统不可能只依赖一个固定数据集完成所有疾病识别，因此需要小样本学习、原型网络、特征增强和后续大模型解释等机制提升系统可扩展性与可读性。

### 2.2.3 目标检测与开放词表检测技术

目标检测技术能够在图像中定位具体对象，是医学影像分析、实验室检测和公共卫生管理的重要工具。YOLO 系列模型具有速度快、部署成熟、工程生态完善等特点，适合实时目标检测场景。开放词表检测和 Agentic Object Detection 则支持通过文本提示指定目标类别，适合样本不足或类别变化频繁的场景。

但传统检测模型通常依赖固定类别训练，对新目标和小样本目标适应不足；开放词表检测虽然具备更强泛化能力，但需要稳定 API、良好提示词设计和结果可视化能力。因此，一个完整系统需要同时支持本地检测模型和外部智能检测 API，使其在不同部署条件下具有更好的弹性。

### 2.2.4 医学知识库与可解释 AI 技术

医疗 AI 的落地难点不仅在于模型“能否给出答案”，更在于答案“是否可信”。知识库、RAG 和知识图谱可以将模型回答与结构化医学知识连接起来，使系统能够返回相关疾病、典型症状、建议检查和处理建议。与纯生成式回答相比，知识增强问诊能够更好地控制幻觉风险，并为医生复核提供依据。

当前许多医疗问答系统仍停留在简单文本匹配或静态 FAQ 阶段，缺乏文档上传、自动切片、检索排序、证据引用和图谱路径展示。DermoAI 将这些能力合并到知识中枢中，使知识从“静态页面内容”转化为“可检索、可更新、可追踪、可参与推理”的系统资产。

## 2.3 本作品要解决的痛点问题

本作品重点解决以下痛点：

1. 皮肤医学初筛依赖专科经验，普通用户无法准确描述症状和判断风险，基层场景难以承担高频咨询压力。
2. 现有 AI 问诊往往只提供文本回答，缺少图像分析、知识证据和上下文记忆，难以形成完整辅助诊断流程。
3. 医学图像识别模型容易受样本规模、光照环境、类别相似度和拍摄质量影响，缺少面向实际使用的解释与报告生成。
4. 医疗知识分散在数据库、PDF、TXT、页面和接口中，缺乏统一入库、检索和图谱化表达。
5. 医疗 AI 系统部署复杂，对 GPU、路径、API Key 和数据库环境依赖强，迁移到企业或教学环境成本高。
6. 管理端缺乏对问诊趋势、症状热度、知识命中率和高风险记录的可视化观察能力，不利于运营优化。

## 2.4 解决问题的思路

DermoAI 采用“多模型协同 + 知识增强 + 产品化工作台”的总体思路，将用户输入、图像上传、模型推理、知识检索、图谱解释和结果展示组织成统一流程。

### 2.4.1 基于 RAG 的智能问诊模块

系统通过 `DiagnosisConversation` 和 `DiagnosisMessage` 保存会话上下文，支持新建会话、历史会话加载、单轮问答、流式问答和会话清理。用户输入症状描述后，系统先调用本地医学知识库和文档切片进行检索，再将检索结果、图谱路径与对话历史拼接成 Prompt，交由大模型生成结构化回复。

该设计避免了纯大模型直接回答导致的不可控问题，使回复能够同时具备语言自然性、知识依据和安全边界。系统提示词明确要求不替代医生诊断、不提供处方剂量、优先识别危险信号，并输出初步判断、追问问题、建议检查、护理建议、就医时机和参考依据。

### 2.4.2 基于 SFEPT 的皮肤影像分类模块

系统在 `app01/ai_core/inference_wrapper.py` 中封装 `SkinFSLPredictor` 单例预测器，使用 Swin Transformer 作为视觉特征提取骨干，并结合 Similarity-to-Prototype 推理结构完成类别判别。预测器启动时加载模型权重和支持集样本，计算各类别原型；推理时对上传图像进行统一缩放、张量化、标准化、特征提取、原型修正和距离计算，最终输出预测类别、置信度与 Top 结果。

与传统闭集分类不同，SFEPT 思路更适合小样本医学图像场景，可通过支持集样本增强类别表达能力；同时系统结合大模型生成影像辅助报告，将模型输出转化为更容易理解的风险提示和就医建议。

### 2.4.3 基于 YOLO 与开放词表检测的目标检测模块

系统保留本地 YOLO 检测流程，支持上传图像、清理历史检测结果、执行推理并返回检测图像；同时在细胞检测模块中接入 Landing AI Agentic Object Detection，通过文本 Prompt 指定检测目标并绘制边界框。该设计使平台既具备本地视觉检测能力，也具备开放词表检测扩展能力。

在工程实现上，YOLO 设备选择由配置项控制，CPU 环境自动关闭半精度推理，降低跨环境部署风险。

### 2.4.4 医学知识中枢与文档入库

系统提供结构化知识条目管理能力，知识条目包含疾病名称、典型症状、建议检查和处理建议；同时支持 PDF/TXT 文档上传，文档入库时自动抽取文本、清洗文本、递归切片、估算 token，并写入 `KnowledgeChunk` 表中。RAG 检索时，系统同时检索结构化知识和文档切片，提升知识覆盖范围。

该模块使平台具备“知识可运营”的能力。企业可以持续沉淀专科指南、内部流程、科普材料和问诊规范，逐步构建私有医学知识资产。

### 2.4.5 数据可视化与运营看板

系统通过 `screen.py` 汇聚会话记录、消息记录、知识库规模、RAG 命中情况、疾病分布、症状关键词和趋势窗口，生成可视化大屏所需数据。数据看板不仅展示系统使用情况，也能辅助观察高风险关键词、知识覆盖不足和用户咨询热点。

### 2.4.6 企业部署与运行适配

系统通过 `.env` 和 `settings.py` 管理关键配置，包括数据库类型、Django 安全配置、大模型 API、讯飞星火 API、Landing AI API、模型路径、推理设备和 YOLO 半精度开关。对于纯 CPU 环境，可配置 `INFERENCE_DEVICE=cpu`；对于 GPU 环境，可配置 `INFERENCE_DEVICE=cuda` 或自动选择。

DermoAI 采用五层架构：

## 2.6 基于 RAG 与知识图谱的智能问诊

智能问诊流程如下：

1. 用户在问诊工作台输入症状描述，系统保存用户消息。
2. RAG 引擎对用户输入进行关键词抽取，检索结构化知识表和文档切片表。
3. 系统根据检索结果构建“疾病—典型症状—建议检查—处理建议”的图谱三元组。
4. 系统将用户问题、历史对话、RAG 证据和图谱路径写入 Prompt。
5. 大模型生成结构化回复，系统以流式方式返回前端。
6. 系统保存 AI 回复、引用依据、图谱路径和模型名称。
7. 数据大屏统计会话量、消息量、RAG 命中率和高风险记录。

该流程使大模型不再是孤立的“文本生成器”，而是被纳入到可检索、可追溯、可复核的医学知识增强链路中。

## 2.7 基于 SFEPT 的皮肤影像辅助诊断

皮肤影像辅助诊断模块的处理流程如下：

1. 用户上传皮肤图像，系统读取文件并转换为 RGB 图像。
2. 图像经过 Resize、ToTensor、Normalize 等预处理操作。
3. Swin Transformer 骨干网络提取高维视觉特征。
4. 系统读取支持集样本，并计算每个类别的原型向量。
5. 对查询图像进行特征提取后，通过 Bias Diminishing 原型修正策略减弱支持集与查询图像之间的分布偏移。
6. 使用 L2 距离或归一化相似度计算类别得分，并输出预测类别和置信度。
7. 系统生成基础医学提示，并可进一步调用大模型生成影像辅助报告。

图位建议：放置 SFEPT 模型流程图或 `sfept_framework.svg`。

## 2.8 目标检测与开放词表检测

目标检测模块采用两种路线：

- 本地 YOLO 路线：适合固定类别、高性能、可离线运行场景。系统上传图像后调用 `app01.yolo.detect.run()` 进行推理，并返回标注后的检测图。
- Landing AI 开放词表路线：适合类别灵活、Prompt 指定目标、样本不足或快速验证场景。用户输入检测目标后，系统调用外部 API 获得检测框、标签和置信度，并在图像上绘制结果。

这种“双检测引擎”设计提升了平台灵活性：既可以支撑本地部署，也可以在需要快速识别新目标时借助开放词表能力扩展系统边界。

## 2.9 健康内容与医学知识服务

健康内容服务由健康习惯、风险提醒、知识主题、药品查询、空气质量和健康妙招等能力组成。其定位不是替代医生，而是提供日常健康管理、科普教育和就医前信息整理。知识中枢则提供专业知识维护入口，支持管理员对疾病知识进行增删改查、内置知识导入、PDF/TXT 文档上传和检索测试。

## 2.10 性能与安全要求

系统设计时关注以下性能与安全目标：

- 响应速度：问诊页面支持流式返回，降低用户等待感；本地模型采用单例加载，避免重复加载权重。
- 部署弹性：支持 CPU/CUDA 自动切换，支持 SQLite/MySQL 切换，支持不同 API 服务商接入。
- 数据沉淀：会话、消息、引用和图谱路径均持久化，便于追踪和统计。
- 医疗安全：提示词和输出规范明确声明“不替代医生诊断”，对高风险症状强调线下就医。
- 配置安全：API Key、模型路径和数据库配置通过环境变量管理，避免硬编码到业务逻辑。
- 可扩展性：模块之间通过 Django View、Service 和 Model 解耦，便于后续加入新模型和新业务入口。

## 3.3 关键算法实现

### 3.3.1 RAG 检索增强生成算法

RAG 模块的核心目标是让大模型回答基于可检索的医学证据。系统首先从用户输入中抽取关键词，然后查询结构化知识表和知识切片表，对候选文档进行简单评分，取 Top 结果作为上下文。随后系统将证据格式化为 Prompt，并与历史会话和图谱路径一并发送给大模型。

RAG 的优势在于：

- 将系统回答限定在本地知识与上传文档范围内。
- 支持企业持续扩展知识库。
- 使回答可附带引用依据和图谱路径。
- 当大模型不可用时，系统仍可返回本地知识库兜底答案。

### 3.3.2 轻量知识图谱构建

系统没有依赖复杂图数据库作为强制组件，而是在本地通过 `GraphTriple` 构建轻量三元组。每条检索知识可拆解为：

- 疾病 -> 典型症状 -> 症状实体
- 疾病 -> 建议检查 -> 检查项目
- 疾病 -> 处理建议 -> 建议内容

这种设计简洁、可解释、易部署，适合中小型医疗知识库和比赛展示场景。若后续接入 Neo4j，当前三元组结构也可平滑迁移。

### 3.3.3 SFEPT 小样本皮肤影像分类

SFEPT 模块以 Swin Transformer 提取视觉特征，以原型学习完成分类决策。核心计算流程为：

1. 对每个类别的支持集样本提取特征。
2. 按类别计算平均特征，形成类别原型。
3. 对查询图像提取特征。
4. 基于支持集和查询集均值差异进行原型修正。
5. 计算查询样本与类别原型之间的距离。
6. 使用 Softmax 输出类别概率。

该算法适合医学图像中“类别多、样本少、标注贵”的场景，也为后续新增疾病类别提供了更好的扩展基础。

### 3.3.4 流式问答与异步输出

系统在智能问诊和讯飞星火聊天接口中均实现了流式输出。智能问诊模块通过 `StreamingHttpResponse` 返回 SSE 事件；讯飞星火模块通过 WebSocket 接收模型分片，再用队列将结果转为前端可消费的流式响应。该设计显著降低用户等待感，使系统交互更接近商业级 AI 产品体验。

## 3.4 数据来源

系统数据来源包括：

- 用户问诊数据：来自平台内用户输入与 AI 回复记录。
- 医学知识数据：来自内置知识模板、后台维护的结构化知识和上传 PDF/TXT 文档。

- 外部 API 数据：来自大模型服务、讯飞星火、Landing AI、健康信息 API 等。

为了符合医疗安全要求，系统在设计上强调辅助诊断定位，不将 AI 输出作为最终诊断结论；真实落地时可进一步加入隐私脱敏、访问审计、加密存储和权限分级。

# 第 5 章 作品总结

## 5.1 作品特色与创新点

DermoAI 的创新不只体现在引入大模型或图像模型，而在于围绕真实医疗辅助场景构建了完整的工程化闭环。

1. 多模态医疗 AI 协同架构  
系统将文本问诊、皮肤影像分类、目标检测、知识检索、图谱解释和数据大屏整合在同一平台中，避免传统 Demo 系统“单点能力强、业务闭环弱”的问题。

2. RAG + 轻量知识图谱的可信问诊机制  
系统不是让大模型直接回答，而是先检索医学知识，再构建疾病、症状、检查和建议之间的图谱路径，最终生成带依据的问诊建议，使 AI 输出更加可解释、可追溯、可复核。

3. 面向小样本医学图像的 SFEPT 分类能力  
系统采用 Swin Transformer 与原型学习结合的 SFEPT 推理框架，能够更好地适应医学图像样本稀缺、类别相似和扩展困难的现实问题。

4. 本地模型与云端智能服务混合编排  
平台同时支持本地 PyTorch 模型、本地 YOLO、Landing AI、DeepSeek/OpenAI 兼容大模型和讯飞星火接口，体现了较强的模型服务编排能力。

5. 企业级可部署设计  
系统支持 CPU/CUDA 切换、SQLite/MySQL 切换、环境变量统一配置和模型路径外置，具备从本地演示走向企业部署的工程基础。

6. 数据资产沉淀与运营可视化  
系统将问诊会话、消息、知识条目、文档切片和图谱路径沉淀到数据库，并通过大屏形成趋势、分布、命中率和风险记录展示，具备持续运营和迭代优化能力。

## 5.2 应用推广

DermoAI 具备以下应用推广价值：

- 基层医疗辅助：为基层医生提供皮肤问题初筛、辅助问诊和风险提示。
- 企业健康管理：为企业员工健康服务平台提供在线咨询和健康内容入口。
- 学校医务室：辅助校医院进行常见皮肤问题咨询和就医引导。
- 互联网医疗平台：作为 AI 能力中台接入问诊、影像分析和知识库管理流程。
- 医学教学科研：用于展示 RAG、知识图谱、小样本图像分类和数据可视化在医疗 AI 中的综合应用。

系统后续可通过私有化知识库、医生复核流程、用户权限分级、报告导出和模型评测体系进一步增强商业落地能力。

## 5.3 作品展望

未来，DermoAI 可在以下方向继续迭代：

1. 引入更严格的医学评测数据集，对皮肤图像分类模型进行多中心、多设备、多光照条件下的泛化评估。
2. 接入真实皮肤镜图像和临床标注数据，提升高风险皮损识别能力。
3. 将轻量知识图谱升级为 Neo4j 等图数据库，实现更复杂的疾病关系推理。
4. 引入医生审核机制，使 AI 建议进入“AI 初筛—医生复核—用户反馈”的闭环。
5. 强化隐私保护，增加数据脱敏、访问审计、传输加密和权限控制。
6. 支持移动端、小程序或企业微信入口，降低用户使用门槛。
7. 增加报告导出、健康档案、随访提醒和长期趋势管理，形成完整皮肤健康管理平台。

DermoAI 以皮肤医学为切入点，但其架构思想可推广到更多医学专科场景。通过“专科知识库 + 多模态模型 + 证据增强 + 企业工作台”的模式，系统具备成为可复制智慧医疗解决方案的潜力。
